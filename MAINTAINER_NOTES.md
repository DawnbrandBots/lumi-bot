# Maintainer (_NotABot_) notes

This repository is very much imperfectly organized. It was initially created with no specific architecture and parts of the code that would belong in different layers according to DDD-oriented layered architecture used to be tightly coupled (still the case in some places, but it's better now).

In #153, I refactored the repository to apply DDD-oriented layer architecture (presentation, application, domain, infrastructure), but did not solve all other code smells that already existed at the same time, nor did I strictly apply all concepts from DDD I initially intended to adopt in this PR. Consequently, some parts of the repository may seem weird. e.g. `infrastructure/` "repositories" are organized by feature (`admin`, `lfg`, `search`) when they should be organized by aggregate roots. Also `domain/` is missing definitions for some entities used by the application.

Changes in this PR from splitting and moving a lot of files around got large and I just wanted to end it. Clearly separating the code into separate layers was enough to enable me to remove some blockers I had with other features I wanted to implement. That is not to say I have given up on DDD and you'll definitely see me doing some more refactoring work later.

Generally speaking, given any part of this repository's code, some design choices were made, but not necessarily following an exhaustive process of elimination leading me to determine that they were superior to all alternatives. e.g. Some code may have been designed to follow (potentially bad) conventions I have defined for the sake of consistency or was rushed because I was getting tired/frustrated by whatever I was implementing and left it at is rather than keep thinking about it 🙃. The repository's design is imperfect, open to be challenged and may be subject to change at any time (hopefully for the better).

I must also admit to relying on coding assistants (Codex specifically) when working on this repository, especially since the LFG feature. If the initial repository design and search feature-related code was my own very-human-non-bot slop, most code around LFG was produced by Codex. I haven't been using coding agents as much before as when working on this project and I am still learning how to use them properly. I have approved changes from Codex without giving them as much attention as I should have to ensure that the code remains clean. As I have learned the hard way, whether using AI or not, the absence of clear guidelines/plans/specifications leads to producing code that may work but is hard to maintain.

This is essentially my main pet project I am working on during my free time. Since I have no deadlines and tend to experiment and overthink a lot, I may take very long to implement even simple changes. Do not hesitate to press me.
